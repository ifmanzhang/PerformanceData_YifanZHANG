# Realtime Baseline Evidence

Original local source:

`artifacts/targets/realtime-baseline-manifest.md`

## Purpose

This local record preserved the point where the project still had a realtime soap-film route. It connected a Huang-clean implementation, cached film data and the frontend structure into a browser-facing baseline.

## What It Demonstrates

- The project did not move straight from concept to final offline video.
- A realtime visual direction existed and was tested.
- The realtime baseline used physics-inspired cache data rather than only a static image or decorative procedural noise.
- The cleanup policy was recorded so temporary render artefacts could be removed without losing the process trail.

## Why It Was Not The Final Method

The realtime route was useful for interaction and future live capture, but the final assessment output needed richer optical detail, droplet density, stable 2160p rendering and reliable classroom playback. The submitted performance therefore kept the realtime system logic at the control-mapping level, but moved capture, simulation and media assembly into a frozen offline pipeline.

## Evidence Value

This evidence supports the claim that offline rendering was a production decision, not a lack of realtime exploration. It also supports the reflection that a later live version could reuse the same control logic with a different visual renderer.
